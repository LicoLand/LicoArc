# Lico Arc Protocol Entity And Configuration Layout

This document is the canonical map of the tracked entities that make up the
Lico Arc Protocol authority and the rules each location follows.

## Rules

- `spec/v1/` and `conformance/v1/` contain the sole initial protocol. Its
  Candidate sources and generated bytes are updated together.
- Each manifest explicitly lists the JSON authorities embedded into its
  bundle and declares its exact wire ID and lifecycle. The manifest is
  embedded as interpretation metadata, and the artifact digest binds those
  fields together with every listed source.
- The v1 locator currently identifies V1 / Generation 1,
  eight mandatory capabilities, user-authority snapshots, and
  confirmation-driven reliable finality.
- Examples and fixtures contain only synthetic values.
- Algorithm and Message Field Decision Workspaces do not enter a Protocol Line
  source closure. Their `OPEN` and `READY` rows are questions, while `DECIDED`
  rows must reference an existing product, architecture, or machine authority.
  Their tracks and statuses remain independent under
  [the canonical lifecycle](DECISION-LIFECYCLE.md).
- `docs/plans/`, `docs/reports/`, `cache/`, and `build/` are local-only and
  ignored; they must never contain tracked material.

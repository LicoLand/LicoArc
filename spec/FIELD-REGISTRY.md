# LicoArc Canonical Field Registry

> Initial V1 / Generation 1 joins user-controlled authority, sibling authority-state
> session binding, and authenticated Endpoint confirmations to the existing
> Pairwise Protection, Generic Message, Reliable Exchange, Group, identity,
> and transport sources. The active registry contains only the current
> initial V1 authority and confirmation surfaces.

This document is the sole normative authority for the active LicoArc logical
field inventory. A schema, Candidate artifact, example, status page,
architecture document, implementation, or field-decision record may project
or implement this registry, but it cannot add, remove, rename, relocate, or
reinterpret a field.

The field-specific documents linked from the `Detailed description（详细说明）`
column explain each field's LicoArc-owned vision contribution, model, risks,
alternatives, comparative evidence, and decision history. They are not a
second field specification. If explanatory prose conflicts with this registry,
this registry wins and the prose must be corrected in the same change.

## Change rule

This registry is intentionally reviewable and may be changed when a concrete
protocol question demonstrates that the current inventory is insufficient or
incorrect. A small mismatch may update a bounded set of rows. A change that
alters layering, authority, identity, or state semantics may replace the table
structure. Every revision must:

1. follow the Message Field Decision lifecycle;
2. preserve decision history through predecessor and successor records;
3. update every affected projection and implementation input in one complete
   migration;
4. remove superseded mutable Candidate fields and compatibility paths; and
5. leave an already Published Protocol Line immutable, allocating a new line
   identity when published bytes or meaning change.

## LicoArc final vision and field contribution rule

This inventory exists only to realize the
[LicoArc final protocol vision](../PRODUCT.md#final-protocol-vision): any
independent conforming Endpoint implementation can use any independent
conforming Station implementation to exchange protected information under one
exact Protocol Line, while Endpoint authority, Station transport limits, and
Network interoperability remain invariant.

The target protocol therefore provides stable portable Endpoint identity,
authenticated and migratable Station affiliation, end-to-end protected
sessions, application-neutral messaging, reliable asynchronous exchange,
privacy-minimal carriage, deterministic failure, independently reproducible
conformance, and federation governance without a privileged implementation,
deployment, Provider, directory, account system, or hosted service.

Every active row states its direct contribution to that vision. An excluded,
replaced, or profile-owned row states which vision property its absence or
relocation preserves. A field cannot be admitted, retained, named, placed, or
interpreted because it is convenient for a product, repository, language,
library, Provider, storage model, deployment, compatibility adapter, or
reference implementation. Those concerns may produce proposals or evidence,
but only a LicoArc-owned interoperable action and completed field-decision
lifecycle can change this registry.

External protocols, standards, libraries, and implementations may supply
bounded comparative, risk, algorithm-lineage, or conformance evidence. They
never define a LicoArc field or contribute missing protocol meaning. The
field-specific detail records keep that evidence separate from each field's
LicoArc-owned vision contribution.

## Common representation rules

- Signed objects, protected records, and bounded claim collections use the
  deterministic CBOR representation selected by
  the containing Protocol Line.
- Field names in this registry are semantic names, not literal wire strings.
  An exact Protocol Line assigns compact unsigned-integer labels to every core
  map key and enum value, uses the shortest deterministic CBOR representation,
  and forbids indefinite-length core values.
- Station submission carries `protectedPacket` as the Transport Profile's raw
  binary body. It is never wrapped in JSON or
  Base64 by LicoArc.
- `ID128` is a 16-octet unpredictable identifier, `DIGEST256` is a 32-octet
  content digest, and `TOKEN256` is a 32-octet unpredictable capability value.
- `M` means mandatory, `C` means conditionally mandatory, and `O` means
  optional.
- Every collection size, byte limit, lifetime, claim bound, retry bound, and
  idempotency window is a fixed Protocol Line or Transport Profile constant.
  A sender cannot raise those bounds on the wire.
- Resumable attachments use Protocol-Line constants
  `MAX_ATTACHMENT_BYTES`, `ATTACHMENT_CHUNK_BYTES`,
  `MAX_ATTACHMENT_CHUNKS`, `MAX_REQUEST_RANGES`,
  `MAX_REQUESTED_CHUNKS`, and `ATTACHMENT_RECOVERY_WINDOW`. Their exact values
  and the recovery window's start event belong to the immutable line.
  `ATTACHMENT_CHUNK_BYTES` is positive and does not exceed
  `MAX_PAYLOAD_BYTES`. No Message or Route can raise, reset, or extend these
  bounds.
- Core objects are closed. Unknown core fields fail closed. Extensibility is
  available only through the admitted `extensions` and `critical` fields.
- Values under endpoint protection are not Station-visible. Protection
  Profile-specific ratchet, counter, key-reference, nonce, and tag fields live
  only in that profile's closed frame schema and are not common fields.

## Protocol overhead and mobile execution invariants

- **User Payload** is the exact application-supplied byte string carried by an
  ordinary Generic Message, including the raw byte slice in an attachment
  chunk. LicoArc does not parse, compress, normalize, rewrite, or otherwise
  transform those bytes. A Payload selected by a reserved LicoArc control
  `contentType` is instead a protocol control structure and must follow the
  exact Protocol Line grammar.
- **Protocol overhead** is every wire octet required by LicoArc or its selected
  Transport and Protection Profiles except the first transmission of ordinary
  User Payload octets. It therefore includes capability and handshake bytes,
  repeated metadata, intrinsic protection framing and authentication tags,
  LicoArc control Payloads, Transport Profile-required bytes, and every
  retransmitted User Payload octet. Canonical encoders and conformance tools
  derive this value; a sender never reports it in a field.
- Every exact Protocol Line fixes positive numeric values for
  `MAX_CAPABILITY_DECLARATION_BYTES`, `MAX_HANDSHAKE_WIRE_BYTES`,
  `MAX_ESTABLISHED_RECORD_OVERHEAD_BYTES`, `MAX_CONTROL_RECORD_BYTES`,
  `MAX_CONTROL_RECORDS_PER_TRANSITION`, `MAX_CONFIRMATION_IDS`,
  `MAX_RETRY_TRANSMISSIONS`, `MAX_ATTACHMENT_STATE_UPDATES`,
  `MAX_ATTACHMENT_RECOVERY_ROUNDS`,
  `MAX_ATTACHMENT_RETRANSMITTED_CHUNKS`,
  `MAX_ATTACHMENT_CONTROL_BYTES`, and
  `MAX_TRANSPORT_OVERHEAD_BYTES_PER_OPERATION`. The line defines the exact
  accounting scope and reset event for each bound. No field, extension,
  retry, reconnect, Route change, or Station migration can raise or reset one.
- The baseline protocol emits no mandatory periodic keepalive, presence, idle
  acknowledgement, discretionary traffic-shaping bytes, synthetic traffic,
  or protocol-induced delay while a relationship is idle or active.
- Each Protection Profile defines implementation-neutral upper bounds for
  protocol state, allocations, wire bytes, control traffic, and work accepted
  before peer authentication. The ordinary established-record path uses
  bounded symmetric ratchet, key-derivation, and authenticated-encryption work.
  Public-key work is limited to bounded establishment, rekey, ratchet, and
  user-authority transitions; ordinary records use the established protected
  session. Runtime measurements and device admission belong to downstream
  implementations.

## Authority boundaries

- `StationDescriptor` fields authenticate replaceable Station discovery; they
  never establish Endpoint identity or mandatory federation membership.
- Station operation fields map bounded `AFFILIATE`, `RESERVE`, `SUBMIT`,
  `CLAIM`, and `SETTLE` behavior. Every operation outcome remains a Station
  Signal; an embedded Station signature proves only its separately defined
  commitment tuple.
- An Endpoint Affiliation Update is the Endpoint-wide current Station-service
  relationship snapshot. Endpoint authentication selects the state; each
  `stationAffiliationSignature` proves only that the named Station accepted its
  opaque, identity-bound commitment for a finite interval. A Route Update is a
  separate peer-relationship-scoped path snapshot and must reference one exact
  accepted affiliation state.
- A valid `stationServiceSignature` makes one asynchronous Route a bilateral,
  time-bounded route binding under a current affiliation; it never proves
  Endpoint identity, user or device ownership, Station honesty or availability,
  message acceptance, delivery, or final effect.
- User-authority, protected-record, message, confirmation, affiliation, and
  route fields are Endpoint-authenticated and hidden from Stations by default.
  A Station observes the opaque affiliation commitment and exact
  control values it signs during `AFFILIATE` or asynchronous `RESERVE`, but not
  `endpointIdentityRef`, `affiliationNonce`, or the complete affiliation and
  peer Route sets.
- Group Membership State is a protected versioned object, not a fourth core
  entity. `groupId` remains stable, `groupEpoch` orders states,
  `previousGroupStateDigest` binds each non-genesis successor, and the bounded
  sorted `members` snapshot carries Endpoint references plus the closed
  `member | state-authority` protocol role. These values authorize only Group
  state transitions and recipient projection; they never create User, Device,
  account, Station, Network, or product-permission authority.
- A Group Message carries one protected `groupStateDigest` as its sole Group
  context. Recipients resolve the exact retained state and derive `groupId`,
  epoch, members, roles, and sender eligibility from it; repeating those
  values is forbidden. A Station cannot interpret, select, or acknowledge
  Group state or membership.
- `protocolLineId`, `protectionProfileId`, `capabilityDigest`, and
  `endpointIdentityRef` are authenticated during session establishment and
  inherited by established records. Their absence from an established record
  saves wire bytes; it does not make them optional state, and repeating them is
  invalid rather than a compatibility form.
- Ordinary User Payload is application authority: LicoArc authenticates and
  carries its exact bytes but does not inspect, compress, rewrite, or assign
  meaning to them. Reserved LicoArc control Payloads remain protocol authority
  and are validated against their exact closed grammars. Neither boundary
  permits plaintext visibility at a Station.
- Attachment descriptors, chunks, exceptional confirmations, and receive state
  remain Endpoint-protected. The declaring `messageId`, `attachmentId`, and
  `chunkIndex` survive retry, restart, re-protection, session renewal, Route
  migration, and Station migration. A Protocol Line change cannot translate
  an active transfer; it requires a new descriptor identity.
- Attachment Receive State is the sole normal progress and completion feedback
  path. Routine successful chunks never cause Endpoint Confirmations; bounded
  aggregate confirmations remain available for non-attachment Messages and
  exceptional attachment rejection or failure. Non-empty recovery state is
  session-authenticated derivative traffic; attachment finality requires all
  authenticated chunks, exact offsets and lengths, the declared content
  digest, and the eligible protected Endpoint confirmation.
- The sender preserves immutable source bytes and original chunk Messages
  until confirmed verified completion, cancellation, terminal failure, or the
  fixed `ATTACHMENT_RECOVERY_WINDOW`. The receiver preserves durably accepted
  chunks and confirmation state to the same payload-release boundary. Both
  peers retain
  the terminal result, immutable tuple bindings, and deduplication tombstones
  through the end of that window even after payload bytes may be released.
  Retry, Route change, Station change, and replay never reset or extend the
  window. Completion, cancellation, and terminal failure are absorbing;
  delayed or replayed recovery state cannot recreate transfer authority.
- Idle relationships are silent at the LicoArc layer. Every control record,
  retry, recovery round, retransmitted Payload octet, intrinsic protection
  expansion, and Transport Profile byte is charged to its exact immutable
  Protocol Line bound. An implementation cannot trade one exceeded bound
  against unused capacity in another.
- Resource bounds are Protection Profile definition properties, never Endpoint
  identity, capability, or device metadata on the wire. Runtime performance
  and device admission are downstream implementation concerns.
- `peerVerificationState`, private keys, plaintext, user approval, Provider
  selection, retry scheduling, quotas, durable
  storage layout, and final local effects remain Endpoint- or
  implementation-local state rather than fields. A conforming Endpoint must
  nevertheless preserve the protocol state it has confirmed until the exact
  terminal or retention transition permits deletion.
- A current mutable Candidate may define only a subset of this registry.
  `docs/STATUS.md` reports that definition fact; Candidate bytes never narrow,
  extend, or override this registry.
